# M3 review findings: fixes, gates and performance

Nine review findings on `m3/capsule-bridge`, all in Fabric's bridge client and journal, verified and fixed on 2026-10-28. Several are reports of one root cause, so five fixes cover them. Each fix has a regression test that fails without it (the mutation or old-client run is named in the table). The protocol's rules and the v1 fixtures are unchanged (`protocol/` has no diff); docs/bridge-protocol.md changes only in its section on Fabric's client as built.

| Finding | Verdict | Fix | Regression test |
|---|---|---|---|
| `observe` trusts the caller's action and locator: a pending destroy recorded `succeeded` while its target lives (high), and the same report from a second reviewer (high) | real: `observe` checked only that the row was `dispatched` or `unknown` | `6539e80`: the log entry carries the action and target, and `observe` refuses before any frame (`ObserveMismatch`) unless it names the operation's action and its target, or for a create the locator its worker reported; a row with no locator has nothing to observe by | `process` `observe_reads_only_the_operations_own_action_and_resource` (fails with the check removed); `capsule_worker` `observe_reads_only_the_operations_own_resource` against the real worker |
| An unknown create reconciled onto another job's sandbox (medium) | real, same root cause | `6539e80` | the other-job cases in both tests above |
| The journal does not keep a request's target, so an unknown exec or destroy loses its resource scope (medium) | real: `provider_begin` wrote no target and the locator stayed NULL until an answer | `0d71e13`: `provider_operations.target` in schema version 2 (which this branch introduces and nothing has released, so the v2 fixture is regenerated by `make_v2_fixture`), written at dispatch, never changed | `fabric-journal` `the_target_is_kept_from_dispatch_through_recovery` and `process` `a_dispatched_destroy_names_its_target_before_any_answer_and_after_a_restart` (both fail when the target is not written) |
| A late answer is dropped unread, losing the created locator (medium) | real: `route` counted it and returned | `d4855fd`: a request Fabric stops waiting on is remembered (at most 1024); a late answer or progress for it is checked like one in time and the locator it names is recorded by `record_late` or the next `request`, `observe` or step. The status stays as the deadline left it | `process` `a_late_answer_records_the_locator_it_names_and_not_its_status` (fails with `late` disabled) |
| Progress frames are not counted: unbounded queue, journal writes, deadline pushed back (medium) | real: only `1..=16` was checked per frame | `83f0ce8`: `seq` must rise by 1 from 1, so at most 16 per request; anything else breaks the protocol and ends the worker. Waiter channels are bounded to 17 | `process` `progress_is_bounded_to_sixteen_frames_in_order` (fails with the order check removed) |
| `request()` is not cancel-safe: a dropped send leaves a partial frame (medium) | real | `42f00c6`: one writer task owns the worker's input and writes each frame whole, in order, by its deadline; `request`, `observe`, `cancel` and `shutdown` record, then queue into a slot reserved before recording, and never wait on the worker | `stream` `a_caller_that_gives_up_leaves_no_partial_frame` (fails on the old client: the first frame never arrives whole) |
| A worker that stops reading blocks `request()`, `close()` and the read loop's terminate path (medium), and the same report from a second reviewer (medium) | real | `42f00c6`: a frame not read by its deadline loses and terminates the worker, as a framing error does; `close` stops the writer at the kill grace; the read loop aborts the writer instead of taking a lock. `44d677a` arms that deadline only when a write blocks | `process` `a_worker_that_stops_reading_is_lost_and_terminated_at_the_deadline` (fails on the old client: `request` never returns) |

The reviewers' own counterexamples were rerun against the built Capsule worker after the fixes (`interop/recheck-before-test.log`, a scratch test that is not committed; `capsule_worker.rs` now holds the same cases): the ghost-locator and wrong-action observes and the other-job observe are `ObserveMismatch`, the pending destroy stays `dispatched` with its target, a destroy lost to a restart keeps its target, and a create answered after its deadline has its locator recorded.

Not changed here, for Capsule: the worker's `observe` does not compare the resource's `fabric.operation` or `fabric.job` label with the observe's operation (finding 8 names `dispatch.ts`). Fabric no longer asks such an observe; the worker-side check would be defense in depth in Capsule's own PR.

## Performance

The machine ran other work throughout: load averages of 10 to 27 on 18 cores (each `machine.txt`). Single runs are noisy at that load, so base (`b3d0311`) and head were run back to back, alternating, against the same worker build, and every sample is kept.

### Bridge round trip and spawn, interleaved (new paths, release)

`ab/ab.sh`: 12 alternating pairs of the release bench, base `b3d0311` and head `d4855fd` (all fixes, before `44d677a`), Rust double and Capsule fixture worker. Raw samples in `ab/writer-task-raw.tsv`, one line per run and path.

| Path | base, median of run p50s | head | head / base, median of 12 pairs |
|---|---:|---:|---:|
| double: spawn and handshake | 2150 us | 2327 us | 1.07 |
| double: round trip, in-memory log | 51 us | 66 us | 1.22 |
| double: round trip, journal | 17.6 ms | 17.1 ms | 1.04 |
| Capsule fixture: spawn and handshake | 39.9 ms | 41.2 ms | 0.99 |
| Capsule fixture: create, in-memory log | 338 us | 313 us | 0.97 |
| Capsule fixture: exec, in-memory log | 296 us | 276 us | 1.05 |
| Capsule fixture: create, journal | 22.1 ms | 20.4 ms | 1.00 |

The one path that moved is Fabric's own share against the double with no journal: the writer task adds a task hop and, before `44d677a`, a timer per frame whose drop takes the runtime's timer lock. `ab/ab-round-trip.sh` then ran 20 alternating triples of that path alone, 2000 trips each (`ab/write-timer-raw.tsv`): base `b3d0311`, head `44d677a` (timer armed only when a write blocks) and a scratch variant of head with no write timer at all. p10 is 45 us, 52 us and 52 us; the median of run p50s 94, 104 and 100 us; the paired ratio to base, median of 20 pairs, 1.17 and 1.05. So the writer task costs about 7 us on a 45 us path, the timer no longer adds to it, and the rest is this machine's noise. Against the real worker and with the journal, where a node spends its time, nothing moved. No path is over 1.5 times its base.

`bench/` is `scripts/bench-bridge.sh` on `b546b03` and `bench-base/` the same script on `b3d0311`, both with the Capsule worker and Docker, kept as the raw record of each commit; they ran 50 minutes apart under different load and Capsule builds, so the interleaved tables above are the comparison.
