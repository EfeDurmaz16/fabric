# ADR 0014: The store as built

Status: accepted, 2026-10-20

Supersedes these parts of ADR 0004: Store layout, the store half of One writer per data directory, Publish, the gc paragraph under Suspend, the file writer paragraph under Restore, the snapshot ref and ignore mechanics under What a workspace snapshot contains, and the catalog line under Consequences. Everything else in ADR 0004 stands: the manifest, the classes of ignored files, the marker, the suspend sequence, the in-place restore and transfer.

## Context

ADR 0004 described the store before any code existed. Building `fabric-store` (PR #7) and three rounds of review changed the layout, the publish order and many capture details. ADR 0004 then carried two amendment blocks that said its own body was wrong, which is the drift ADR 0009 forbids. This ADR records what the crate does and why. Each rule that can fail has a test, named in the Consequences.

## Decision

### Store layout

```text
store/
  objects/ab/cdef...   one object per file, one zstd frame, named by blake3 of the uncompressed bytes
  catalog.sqlite       schema_version, settings, chunks, snapshots, snapshot_chunks
  tmp/                 scratch files of the lock holder; cleared at open and by gc
  lock                 flock target
```

- There is no `manifests/` directory. A manifest's bytes are objects like any file's, by the same rule (one object up to the whole-file limit, FastCDC above it). `snapshot_chunks` records the manifest's object ids in order, with the role `Manifest`. A reader assembles them, checks the length and that the bytes hash to the `SnapshotId`, and only then decodes, under the 64 MiB bound. An assembled copy on disk would be a second thing to keep consistent.
- `settings` holds the chunking parameters and the zstd level the store was created with. They are fixed for the life of the store, so the same bytes give the same ids on every node with the same settings.
- `chunks` holds each object's id, its length on disk, its refcount and the time its last reference went. The refcount is the number of `snapshot_chunks` rows that name it, and `Store::check` recomputes it. At hash depth `check` also assembles every manifest whose objects are whole, checks its length and id, decodes it and compares the data objects it names with the catalog's rows and its job, parent, bundle base and creation time with the snapshot row, and names a snapshot that fails in `bad_manifests`.
- There is no `jobs` or `pins` table. They belong to the crate that owns the ledger.
- The catalog runs with `journal_mode=WAL`, `synchronous=FULL` and `fullfsync=ON`. It is built under `catalog.sqlite.tmp` and renamed into place after the schema commits, so a `catalog.sqlite` that exists is complete.

### One writer

`Store::open` and `Store::create` take an exclusive `flock` on `<store>/lock` and fail with `StoreError::Locked { path }` when another process holds it. They wait at most one second: a child that another thread forks shares the lock's open file until it execs, so a lock this process has just released can look held for that instant. The parallel test suite hit this when a test reopened its store. The data-directory lock, the node socket and the split of work between the node and the CLI in ADR 0004 are the job crate's; it opens the store under its own lock, so the two never race.

### Objects

- `ChunkParams` is built only by `ChunkParams::new`, which keeps FastCDC's rules (`64 <= min <= avg <= max`, average from 256 bytes to 4 MiB) and bounds `max_size` and `whole_file_limit` by `MAX_OBJECT_LEN`, 8 MiB. No object is larger than the bulk frame of ADR 0005: `put` refuses longer bytes with `TooLarge`, which matters for a caller that stores bytes a peer sent, and `read` sizes its buffer from that bound, never from a frame header alone.
- An object is written to `tmp/`, flushed with a plain `fsync`, and hard-linked to its final name. A name that exists is never replaced, so two writers of the same object cannot replace each other's bytes. A reader refuses a file longer than zstd's compression bound for `MAX_OBJECT_LEN` before it loads it, then decompresses and checks the hash before it hands bytes out.
- `put_file` opens with `O_NOFOLLOW` and `O_NONBLOCK` and checks the type on the open descriptor. A symlink, FIFO, socket or device is refused with `NotRegular`; it is never followed, and a FIFO never blocks. `put_reader` reads at most the whole-file limit plus one byte at once and streams anything longer through FastCDC, so a file that grows while it is read is never held whole.
- No hard links from the store into a workspace. Objects are compressed, so a link would hand the harness a zstd frame, and a tool that edits a file in place would rewrite the store's copy. Restore always writes bytes.

### Publish

`Store::publish` makes a manifest a published snapshot. The caller appends `SnapshotPublished` to the ledger afterwards, so the ledger stays the commit point (ADR 0002).

1. Refuse a manifest whose encoding is above `MAX_MANIFEST_LEN`, 64 MiB, with `ManifestError::TooLarge`; every reader, this store's included, refuses to decode it. Capture checks the same bound, so the user hears it while the workspace is still there. Reading a manifest checks the catalog's recorded length against the bound before it allocates.
2. Refuse a `bundle_base` the catalog does not have (`MissingBundleBase`).
3. Every object the manifest names must be on disk (`MissingChunk` otherwise). These are `Store::data_chunks`: the bundle, the exclude file, every file and harness-state object, and, since 2026-10-22, the environment spec the manifest names in `env_spec`, stored by `Store::put_env_spec` as one object whose id is the spec's id (ADR 0007, amended 2026-10-22). An object that has no catalog row, and that this process did not link since its last flush, may come from a process that died before its flush; after a power loss its name can survive without its bytes. Publish re-reads and verifies such an object. A corrupt one is removed and publish fails with `CorruptUnpublished`, so the next capture writes it again. A good one has its shard directory marked for the flush.
4. Refuse a file entry whose objects, by their frame headers, do not add up to the size it records (`SizeMismatch`); restore would write the file and then fail. Write the manifest's bytes as objects. The same rule as step 3 applies to them.
5. Flush every marked shard directory with `F_FULLFSYNC` (`fsync` on Linux). A flush that fails keeps its shards marked.
6. One transaction inserts the snapshot row, the new chunk rows and every reference.

Each object gets a plain `fsync` when it is written, and the shard directories get the one full flush. This is the split git's `core.fsyncMethod=batch` makes. With `F_FULLFSYNC` per object the bench captured 5,022 files in 20.7 s, 4 ms per file; with the split it took 1.8 s when the crate was written. Publishing a manifest the store already has returns its id and changes nothing.

What this survives: a kill at every step, which the crash test proves by killing after the objects, after the flush, before the commit and after it; in every case `check` finds no row naming a missing object and a rerun ends in a clean store. A power loss after step 6, because every object a row names was flushed, or verified and flushed, before the row.

### gc

gc has two passes. One pass stamps chunks whose refcount reached zero; a later pass deletes stamped chunks once the grace has passed, the row first and the file second. An object file with no row, which a publish that died before its transaction leaves behind, is removed once its mtime is older than the grace. `tmp/` is cleared at open and at every gc.

gc must not run between a capture and the publish of its manifest. Capture can reuse an object that is on disk without a row, and `put` does not refresh its mtime; a gc in between can remove it, and publish then fails with `MissingChunk`. That fails closed, and the capture must run again. The lock holder runs capture and publish as one step.

### Losing the catalog

A lost or corrupt catalog cannot be rebuilt from `objects/` alone. The order of a manifest's objects exists only in `snapshot_chunks`. A manifest of 8 MiB or less is one object and could be found by trying to decode every object, but a larger one is lost with the catalog, and so is every snapshot whose manifest is above the whole-file limit. The recovery path is a peer: the snapshot ids are in the ledger, which is a separate file, and a node fetches the snapshot again by id (ADR 0005). Making a single node self-recovering would need a small object per snapshot that lists its manifest's object ids; it is not built.

### Capture: the git half

- `I` is built from a copy of the index in `tmp/`, retried while `index.lock` exists and then refused with `GitBusy { IndexLocked }`. `W` is built in a private index seeded with `I`'s tree, by `git add -A`. Every tracked and untracked path is stamped (device, inode, size, mtime) just before `git add -A`, and the mtime pass after `W` fails with `WorkspaceChanged` on a path of `W` whose stamp changed, so an edit made while `W` was built is not lost behind an old blob.
- One exclude set. Git reads the user's default exclude file (`$XDG_CONFIG_HOME/git/ignore`, else `~/.config/git/ignore`) even with the global config off, while `-c core.excludesFile` replaces it. Capture therefore resolves that file once (or the repository's own `core.excludesFile`) and passes it explicitly to the untracked listing, the ignored listing, the LFS listing and `W`. For `W` the policy's secret and exclude patterns follow it in the same file. They are positive patterns only, so a path the ignored listing names is never in `W`. Before the manifest is validated, capture checks that no path is in both `files` and `W`, and fails with `IgnoredAndInWorktree` if one is: restore checks out `W` and then creates `files` exclusively, so such a snapshot would publish and never restore. `SnapshotManifest::validate` refuses the same overlap between `files` and `worktree_mtimes` (`InBothTrees`), so a manifest from a peer or from the publish API holds the rule too. It also refuses the two trees nesting (`TreesNest`): a `files` entry below a working-tree path, which is a file, a symlink or a submodule, and a `files` file or symlink above one, where checkout already made a directory. Restore could write neither. A `files` directory above a working-tree path is the parent the two trees share and is accepted. A `core.excludesFile` set only in the user's global config is not read, like the rest of that config; a file it ignores is untracked to capture and travels in `W`.
- Secrets and `W`. A negation in the repository's own ignore files outranks `core.excludesFile`. After `add -A` the private index is listed, and every untracked path the policy denies is removed before `write-tree`. An untracked nested repository is excluded up front and removed too.
- Secrets in the stash. The bundle carries `refs/stash` with its parents, and after `git stash -u` the third parent holds untracked files, a `.env` among them. Capture lists the trees of every stash entry and of its index and untracked parents, and names every path a secret pattern matches in `stashed_secrets`, next to `tracked_secrets`. Like a committed secret, it is already in the user's object store, so it is named, not refused.
- Every stash entry travels. The bundle carries refs, not reflogs, so capture points `refs/fabric/<job-id>/stash/<n>` at `stash@{n}` for every entry older than `refs/stash`, removes the job's earlier ones, and after the bundle checks that the stash list did not change. Restore rebuilds the stash reflog oldest first from those refs, so each entry comes back at its index.
- Directories. A git tree records no directory and `ls-tree -r` names only leaves, so capture lists the trees of `W` and carries each directory's mode and mtime as a directory entry in `files`, which restore applies after the children. An empty directory, untracked or ignored, is in no git listing; a walk of the work tree that skips repositories and the paths `W` holds finds it, and it passes through the policy with the ignored files, so it gets a directory entry, its parents get theirs, and a cache root among them gets its row.
- The snapshot ref is `refs/fabric/<job-id>/snap/<W>`, named by the commit it points at. The job's older snapshot refs are deleted before the refs are read, so they never enter `GitState.refs`.
- Refs are proven, not assumed. Capture reads the refs and `HEAD`, makes the bundle, reads them again, and checks the bundle's list of heads. A ref the bundle lists must have the recorded id; a full bundle must list every ref; a ref an incremental or empty bundle leaves out must be reachable from the parent's tips, which earlier bundles of the chain carry. Anything else is `RefsMoved`, and the caller captures again. Without this, an IDE's autofetch between the bundle and the listing recorded a tip no bundle held, and every later incremental bundle excluded it too.
- The bundle is full when there is no parent, after 16 incremental links (`MAX_BUNDLE_CHAIN`), when a parent tip is gone from the repository, or when the incremental bundle fails `git bundle verify`. When the parent's refs already reach every object, git refuses to write an empty bundle; the manifest then has an empty `bundle` with `bundle_base` set, and restore skips it.
- Refusals, each before anything is published: a root git cannot read, as when `safe.directory` refuses a repository another user owns or its config does not parse (only "not a git repository" makes a root a plain directory), a root inside a repository but not its top level (`NotRepositoryRoot`), a linked worktree (`GitLinkedWorktree`), a rebase, merge, cherry-pick, revert or bisect in progress, a held `index.lock` or unmerged entries (`GitBusy` with the reason; an index copy that a lock or a rename raced is taken again), an index entry marked intent-to-add, skip-worktree (sparse checkout) or assume-unchanged, whose state neither commit can hold (`GitIndexFlag`), a submodule with local changes, named by its whole path, also when `submodule.<name>.ignore` would hide them or the submodule was renamed (`GitSubmoduleDirty`), an mtime before 1970, which the manifest's unsigned time cannot hold (`MtimeBeforeEpoch`), a shallow clone, whose boundary the bundle cannot carry (`GitShallow`), a path with `filter=lfs` by git's own `check-attr` (`GitLfsUnsupported`), a path whose `filter` attribute names a driver with a non-empty `clean` or `process` command in the config git reads for the repository (`GitFilterUnsupported`; added 2026-10-22, below), and untracked files above 64 MiB unless allowed (`UntrackedTooLarge`).
- The config projection keeps the allowlisted keys of ADR 0004. A remote URL, in `remote.<n>.url`, `remote.<n>.pushurl` or `branch.<n>.remote` (which git also reads as a repository URL), loses the part that can hold a credential (`fabric_core::git::credential_range`): the whole `user[:password]@` for `http`, `https` and other schemes, only `:password` for `ssh`, `git+ssh` and `ssh+git`, whose user name picks the account. A key git holds more than once, such as a second `remote.origin.fetch` refspec, travels with every value in git's order, and restore writes them back in that order. The report names keys whose URL was stripped (`stripped_userinfo`) and keys left behind because `GitConfigValue` refuses the value or because a remote URL has a query or a fragment, where a token such as `?access_token=` travels (`dropped_config`); a manifest that carries such a URL fails to decode. Restore writes every carried key except `core.ignorecase` and `core.symlinks`: they describe the source's filesystem, and `git init` has already probed the target's, so a macOS snapshot restored on case-sensitive ext4 keeps `core.ignorecase=false`.
- How git runs. Every inherited `GIT_*` variable is removed before the sandbox ones of ADR 0004 are set, and git runs with `LC_ALL=C`. The source repository's own config is the user's and is honored there: its filters run during `git status` on capture, as for any git command the user runs. On the target only the projection exists. Amended 2026-10-22 after review: a clean filter the repository configures, git-crypt's among them, is refused instead of run into `W`. `git add -A` stores what the clean step makes of a file, and restore writes blobs with `cat-file`, with no smudge step and no filter config, so the target would hold ciphertext where the agent had plaintext while `git status` called the tree clean. Carrying the raw bytes instead would put git-crypt's plaintext into the bundle, which is what the filter exists to prevent. A driver counts when the config git reads for the repository, includes too, gives it a non-empty `clean` or `process` command; an attribute that names a driver with neither changes no bytes and is not refused. Other check-in conversions, line endings by `text`, `eol` or `core.autocrlf`, `ident` and `working-tree-encoding`, do not change what travels: a file whose blob differs from its bytes hashed with no filters gets its own bytes in `W`, so restore writes the file the agent had; a path under a `filter` attribute keeps git's output there and is named in the report (`filtered`). `commit-tree` ignores `commit.gpgSign`, so no signing program runs.

### Capture: the files half

- Listing. A plain directory and the harness state directory are walked without following links. Each listed path is a directory, a regular file or a symlink; a FIFO, socket or device is skipped and named in `special_files` or `special_harness`. A `.git` in any case, a directory or the file of a linked worktree or submodule checkout, is skipped, and the directory holding it is named in `nested_repositories` (or `nested_harness`); its other files are carried.
- Reading. A listed file is opened by a walk down from the root of the listing through directory handles, each component with `O_NOFOLLOW`, the file itself with `O_NOFOLLOW` and `O_NONBLOCK`, and read only if the open descriptor is a regular file with the device and inode the listing saw. A file swapped for a link to `~/.ssh/id_ed25519` between the listing and the read fails with `WorkspaceChanged`, and so does a directory swapped for a link to `~/.ssh` after it was listed, so a secret never enters the store under a harmless name. A link's target is read the same way. After the read, the open file's size and mtime must still be the listing's, so a file written to during the read fails with `WorkspaceChanged` instead of being stored torn. Capture is meant to run on a suspended job; this catches a harness that was not stopped.
- Classes. ADR 0004's table reads as if any `out`, `build`, `dist`, `target`, `vendor` or `.cache` were a cache. As built, a generic name is a cache only beside the file of the tool that makes it: `target` needs `Cargo.toml` or `pom.xml`, `out` and `.cache` need `package.json`, `dist` and `build` need a node, python, gradle or cmake file, and `vendor` needs `go.mod`, `composer.json` or a `Gemfile`. Names only a tool makes need none. A directory the job adds through `IgnorePolicy::add_cache_dir` needs none; that is where the `EnvSpec` plugs in. A path's class and its cache root are one value: `Secret` or `Excluded` with an optional root, `Cache` with its root, or `Precious`. Every cache root the listing meets gets a row, one that holds only directories too, so restore can ask the target about it. A row is `Carried` when nothing under it was denied or excluded, `NotCarried` when nothing under it travels, and `Partial` otherwise; restore treats `Partial` as missing, whatever the target's carry rule says.
- Secret and exclude patterns compare names with ASCII case folded, as APFS and git with `core.ignorecase` do. `.fabricignore` holds excludes only. A `**` past the leading `**/` is refused, in `.fabricignore` and from a caller, because git matches it across any number of directories and the policy's matcher does not. The secret list can be widened, never narrowed. The harness state directory gets the full secret list too; its denied paths are named in `denied_harness`.
- Carry keys are measured outside this crate. Capture takes a `CarryKeys` implementation. `UnmeasuredKeys` writes `CarryKey::Unmeasured`, and `CarryKey::matches`, the comparison of ADR 0012, never accepts it, not even against itself.
- Scratch files (index copies, exclude files, bundles) live in the store's `tmp/` and are removed on every path. Nothing is written into the user's `.git` except the two commits, the snapshot ref, the job's stash refs and the deletion of the job's older snapshot and stash refs.

### Restore

- This crate does the fresh case of ADR 0004's Restore step 2: the target must be absent or empty, the tree is written into `<target>.fabric-restoring`, verified when asked, and renamed onto the target. The marker and the in-place path are the job crate's.
- `git init` gets the object format of the manifest, read from the width of `index_commit`, so a SHA-256 repository restores.
- The bundle chain is walked from the manifest's `bundle_base`. A base the catalog does not have is `BundleChainBroken`. Publish refuses an unknown base and `forget` refuses a snapshot a remaining one names as its base (`BaseInUse`), so only a damaged catalog reaches that error.
- A tree name that is not UTF-8 is refused (`BadTreeOutput`), never decoded lossily into another name.
- Refs come from the manifest alone. Each bundle of the chain is checked with `git bundle verify` and unpacked with `git bundle unbundle`, which indexes its pack and writes no refs; then every ref in `GitState.refs` is set with `git update-ref`. This replaces the fetch of ADR 0004's Restore step 4.2. A fetch with `+refs/*:refs/*` creates every ref an older link lists, so a branch `feature` replaced by `feature/x` between two snapshots failed the fetch, and the newer snapshot published and never restored.
- Verify compares a file byte for byte, a link by its target and a directory by its type, so a removed empty directory or a replaced link fails like a changed file. A file is opened with `O_NONBLOCK` and its type checked on the descriptor, so a FIFO or device in its place fails at once instead of blocking.
- Directories are created owner-only and get their recorded mode after their children, deepest first, with their mtimes. A directory captured read-only, such as a Go module cache or a `chmod -w` fixture, would otherwise refuse its own files. A rerun gives the owner write and search permission on every directory of a stale staging tree before it removes it.
- `Durability::PowerLoss` flushes every written file after its mtime is set, every directory of the staging tree after its mode and mtime, and runs git with `core.fsync=all` and `core.fsyncMethod=fsync`; the rename's directory flush then empties the drive cache. A file's flush does not make its name durable, so the directories are flushed before the rename that publishes them. `ProcessCrash` relies on the kernel finishing issued writes.
- With harness state, the harness directory is renamed into place just before the workspace, whose rename stays the commit point. A rerun that finds the harness directory complete, holding exactly the manifest's paths with the stored bytes, keeps it, and under `PowerLoss` flushes its files and directories, since the run that wrote it may not have. A harness directory inside the target, or a target inside it, is refused with `NestedDirectories`: the first rename would fill the other directory, and every rerun would stop at a target that is not empty.
- The file writer opens every component through a directory handle with `O_NOFOLLOW`, using rustix's `openat`, in place of `cap-std`. It creates files with `O_EXCL` in place of ADR 0004's case-folding probe: two files whose names fold together fail with `Collision`, but two directories that fold together are merged, which only a manifest from a case-sensitive peer can hold. The probe and `PathCollision` stay planned for the in-place restore.

## Alternatives considered

1. **Rewrite ADR 0004 in place.** ADR 0009 says an ADR is superseded, not edited, except for errors of fact; ADR 0013 does the same for the network protocol (PR #5). Rejected.
2. **Keep an assembled manifest file.** A second copy to keep consistent with the objects; it would make the catalog recoverable for large manifests but not the refcounts or the chain. Rejected; the recovery path is a peer.
3. **Full flush per object.** Measured at 4 ms per file on APFS, minutes for a `node_modules`. Rejected for the batch split.
4. **Trust every object file that exists.** Cheapest, and after a power loss it publishes a snapshot that only fails at restore, when the source bytes may be gone. Rejected for verifying the objects without a row that this process did not write.
5. **Read refs after the bundle.** What the first version did; it records tips no bundle holds when a ref moves in between. Rejected for the proof above.

## Consequences

- A capture on a machine whose global git ignore names a file the project creates, such as Claude Code's `.claude/settings.local.json`, restores. Test: `a_file_only_the_global_ignore_names_restores`.
- A ref that moves while capture runs fails the capture with `RefsMoved` instead of publishing a snapshot that cannot restore. Test: `a_ref_the_bundle_does_not_hold_is_refused`.
- A FIFO or socket in the workspace or the harness state is named and left behind, and a file replaced after its listing fails the capture. Tests: `a_fifo_or_socket_is_left_behind_and_named`, `a_file_replaced_after_its_listing_is_refused`, `a_path_that_is_not_a_regular_file_is_refused_unread`.
- Publish never names a corrupt or unflushed object it did not write. Test: `a_corrupt_object_left_without_a_row_is_removed_not_published`; the crash matrix kills publish at every step.
- The bundle after 16 incremental links is full, and a parent whose tips were pruned gets a full bundle that restores. Tests: `the_bundle_after_the_longest_allowed_chain_is_full`, `a_parent_tip_gone_from_the_repository_makes_a_full_bundle`.
- A branch replaced by a directory of branches of the same name, or the reverse, across an incremental link restores. Tests: `a_branch_that_becomes_a_directory_of_branches_restores`, `a_directory_of_branches_that_becomes_a_branch_restores`.
- A read-only directory that holds files restores, and a restore killed after the modes were applied finishes on rerun. Tests: `a_read_only_directory_that_holds_files_round_trips`; the restore crash matrix has read-only directories in the workspace and the harness state.
- A `.env` saved with `git stash -u` is named in `stashed_secrets`. Test: `a_secret_saved_in_the_stash_is_named`.
- Every stash entry comes back at its index. Test: `every_stash_entry_survives_capture_and_restore`.
- A file git converts on check-in restores with its own bytes, and a path under a clean filter the repository configures is refused. Tests: `a_file_git_converts_on_check_in_restores_with_its_own_bytes`, `a_path_under_a_configured_clean_filter_is_refused`.
- A directory keeps its mode and mtime, and an empty directory in a repository restores. Tests: `a_tracked_directory_keeps_its_mode_and_mtime`, `an_empty_directory_in_a_repository_round_trips`.
- A manifest above the decode bound is refused at capture and at publish instead of publishing a snapshot no node can read. Test: `publish_refuses_a_manifest_no_reader_would_decode`.
- A lost catalog loses every snapshot whose manifest is above the whole-file limit until a peer sends it again.
- `fabric orphan export` must pin the whole bundle chain of the snapshot it exports, not only the snapshot.

## Open questions

- APFS `clonefile` for restore. Objects are compressed, so a clone would need raw objects on the same volume. Measure whether per-file writes of a 100,000-file `node_modules` are slow enough to pay for a second object format.
- gc between a capture and its publish is ruled out by the lock holder running them as one step, not by the types. It fails closed with `MissingChunk`. A capture that holds `&mut Store` until it publishes would make the borrow checker enforce it; decide when the daemon (PR #8) settles how it calls capture.
